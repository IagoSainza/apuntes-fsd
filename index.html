Terminal (Unix)

Moverte por carpetas y gestionar archivos sin ratón. Antes de hacer algo peligroso: pwd y ls para saber dónde estás.

Lo esencial

  • pwd dónde estoy · ls qué hay aquí. Si te pierdes, estas dos.
  • cd carpeta entra · cd .. sube · cd ~ a tu usuario.
  • mkdir crea carpetas · touch crea archivos · cp copia · mv mueve o renombra.
  • rm borra para siempre (no hay papelera). rm -rf sin preguntar: cuidado.
  • Si un nombre tiene espacios, va entre comillas: cd "Trabajo clase".

Tu entorno de trabajo

  • Terminal (Warp o Git Bash): la ventana donde escribes comandos. En Windows se configura Warp para que use Git Bash, así los comandos son iguales que en Mac/Linux.
  • VS Code: el editor donde escribes el código. Extensiones recomendadas: Prettier + Format on Save (te ordena el código al guardar) y VS Code Icons (iconos para ver qué es cada archivo).
  • Node.js (versión LTS): permite ejecutar JavaScript en la terminal sin navegador: node archivo.js.

Git

Git guarda "fotos" (commits) de tu código. Un archivo pasa por tres sitios: carpeta de trabajo → staging (preparado) → commit (guardado) → y luego al remoto (GitHub).

Lo esencial

  • Un cambio pasa por: carpeta → add → staging → commit → historial → push → GitHub.
  • git status a todas horas: te dice en qué rama estás y qué falta por guardar.
  • Una rama por tarea: git switch -c feature/algo. Al acabar: push, Pull Request y merge en GitHub.
  • Antes de empezar: git switch main + git pull. Commits pequeños con verbo: "Añade…", "Corrige…".
  • Nunca git init dentro de otra carpeta que ya tenga Git. El repo del profe: solo git pull, no se toca.

El ciclo que harás siempre

editas código→git status→git add .→git commit -m "mensaje"→git push
git switch -c feature-login        // 1. creo rama nueva y me cambio a ella
git status                         // 2. ¿qué he cambiado?
git add .                          // 3. preparo todos los cambios
git commit -m "Login con JWT"      // 4. guardo una versión
git push -u origin feature-login   // 5. la subo (-u solo la primera vez)

Trabajo en equipo con GitHub

GitHub es la web donde se guarda el repositorio en la nube para compartirlo. Para conectarte se usa un token (PAT) en vez de contraseña.

Orden para no pisar el trabajo de nadie:

git fetch origin main→git pull origin main→git push origin main
  1. fetch: mira si hay algo nuevo en GitHub, sin tocar tus archivos.
  2. pull: lo descarga y lo junta con lo tuyo.
  3. push: sube tus commits.
  • Una rama por tarea (feature/login). No se trabaja directamente en main ni develop.
  • git checkout -b feature/login hace lo mismo que git switch -c: crea la rama y te cambia a ella.
  • Conflicto: dos personas cambiaron las mismas líneas. VS Code te deja elegir: Accept Current (lo tuyo), Accept Incoming (lo que llega) o Accept Both (las dos). Luego haces commit.
  • Nunca hagas git init o git clone dentro de otra carpeta que ya es un repositorio.

Diagrama: la rama de cada ejercicio

Línea de arriba: main. Sales de ella con una rama nueva (abajo), haces tus commits (puntos naranjas), la subes con push y vuelve a main con la Pull Request. Después actualizas main en tu ordenador.

Flujo de trabajo con una rama

Sirve para cada ejercicio o cada cosa nueva que hagas. Si lo sigues en orden, Git no da sorpresas:

  1. Partir de main actualizado: git switch main y git pull.
  2. Crear la rama del ejercicio: git switch -c feature/ejX-nombre. Si ya existe, sin -c.
  3. Programar por pasos y hacer un commit cada vez que un paso funciona: git add archivo + git commit -m "Verbo + qué hace".
  4. Si usaste IA, decláralo como lo pida el profe.
  5. Explicar lo que has hecho en el README antes de cerrar la rama.
  6. Comprobar: git status tiene que decir nothing to commit, working tree clean.
  7. Subir la rama: git push -u origin feature/ejX-nombre.
  8. En GitHub: Pull Request → Merge pull request → Confirm merge. No borrar la rama.
  9. Volver a main: git switch main y git pull.

git add archivo solo mete ese archivo en el commit. git add . mete todo lo que has cambiado. Lo que esté en verde en git status es lo que entrará.

Mensajes de commit: empiezan por un verbo en presente y dicen qué hiciste ("Calcula la media", "Corrige el saludo vacío"). Nada de "cambios" o "fix".

Gitflow: para qué sirve cada rama

  • main: solo versiones que funcionan (v0.1, v1.0…).
  • develop: donde se junta el trabajo del día a día.
  • feature: una rama por funcionalidad; sale de develop y vuelve a develop.
  • release: se prepara una versión; va a main y a develop.
  • hotfix: arreglo urgente desde main; vuelve a main y a develop.

HTML + JavaScript en el navegador

Cuando escribes www.marca.com, el DNS lo traduce a una IP (ej. 234.45.64.78) y el navegador pide la página por http/https. Recibe HTML y lo pinta.

Lo esencial

  • El navegador pide la página y recibe HTML (estructura), CSS (aspecto) y JS (comportamiento).
  • El <script> va al final del <body>, para que el HTML ya exista cuando JS lo busque.
  • JS en el navegador cambia la página; JS con Node funciona en la terminal o en un servidor, sin página.

Dónde poner el <script>

<head>
  <title>Document</title>
  <!-- zona 1: aquí aún NO existe el <h1> -->
</head>
<body>
  <h1>Titulo de la pagina</h1>
</body>
<!-- zona 2: al final, cuando JS va a modificar el HTML -->
<script src="main.js"></script>

Por qué al final: el HTML se lee de arriba abajo. Si el script va antes, intenta buscar el h1 y todavía no existe.

main.js: cambiar el HTML desde JS

const h1 = document.querySelector('h1') // busco el primer <h1>
h1.textContent = "hola"                 // le cambio el texto
  • document = la página entera, vista desde JS.
  • const h1 = ... = guardo ese elemento en una variable para usarlo.
  • querySelector('selector') = busca un elemento como en CSS ('h1', '.clase', '#id').
  • textContent = el texto de dentro.

Dos formas de ejecutar JS: en el navegador (con HTML) o en la terminal con node archivo.js.

Condicionales (control de flujo)

Hacen que el programa tome un camino u otro según una condición que da true o false.

Lo esencial

  • if / else if / else entra solo en el primer camino que se cumple.
  • Por eso la condición más exigente va arriba (≥ 9 antes que ≥ 5).
  • El else no lleva paréntesis: es "en cualquier otro caso".
  • if + if son preguntas independientes (pueden cumplirse las dos); else if es una sola decisión.
  • Sin ; detrás del if (...): si lo pones, el if no hace nada.

if · if/else

// if: solo se ejecuta si la condición es true
if (edad >= 18) {
  console.log("Eres mayor de edad")
}

// if/else: un camino u otro, siempre entra en uno
if (temperatura > 25) {
  console.log("Hace calor")
} else {
  console.log("No hace calor")
}

else if: varias opciones

if (edad >= 0 && edad < 18) {
  console.log("Eres menor de edad")
} else if (edad >= 18 && edad <= 110) {
  console.log("Eres mayor de edad")
} else {
  console.log("Valor no valido")   // -30, 123…
}
  • Se comprueba de arriba abajo y entra solo en el primero que cumpla.
  • Pon primero la condición más restrictiva y al final la más genérica.
  • El else final recoge "todo lo demás" (valores no válidos).

Diagrama: if / else if / else (ejemplo de notas)

Pregunta de arriba abajo y entra solo en el primer camino que cumple. Los demás se los salta. Por eso las condiciones más exigentes van primero. Al final, todos los caminos siguen por el mismo sitio.

switch: comparar un valor con muchos casos

switch (color.toLowerCase()) {   // 'ROJO' → 'rojo'
  case "azul":
    console.log('blue')
    break                        // ¡sin break sigue al siguiente!
  case "rojo":
  case "bermellon":              // dos casos, mismo resultado
    console.log('red')
    break
  default:                       // si no coincide ninguno
    console.log('no esta en el diccionario')
}

Cuándo usarlo: cuando miras si una variable es igual a valores concretos (colores, días…). Para rangos (>, <) usa if/else if.

Operador ternario: if/else en una línea

// condición ? valorSiTrue : valorSiFalse
const texto = estado ? "Encendido" : "Apagado"

// es lo mismo que:
let texto2
if (estado) { texto2 = "Encendido" }
else { texto2 = "Apagado" }

Úsalo para elegir entre dos valores simples. Si hay más lógica, if/else.

Ayuda a evitar el "Hadouken code": muchos if dentro de if, con el código cada vez más metido hacia la derecha.

Bucles (repetir código)

Un bucle repite un bloque de código mientras se cumpla una condición. Así no escribes lo mismo 100 veces.

Lo esencial

  • for (inicio; condición; paso): pregunta → hace lo de dentro → cambia i → vuelve a preguntar.
  • En la primera vuelta i vale lo del inicio; el paso (i++) se hace al final de cada vuelta.
  • Para recorrer un array: i < lista.length (no <=), y recorre la lista que estás procesando.
  • for…of te da cada valor, sin posición. Si necesitas la posición, for con i.
  • Lo que va dentro del bucle se repite en cada vuelta; lo que va después, una sola vez.

for: cuando sabes cuántas vueltas

for (let i = 0; i < 5; i++) {
  console.log(`Vuelta número ${i}`)   // 0, 1, 2, 3, 4
}
ParteQué hace (en sencillo)
let i = 0Empieza a contar en 0.
i < 5Sigue mientras i sea menor que 5.
i++Al acabar cada vuelta suma 1 a i.

while y do-while

let n = 0
while (n < 3) {       // mira la condición ANTES
  console.log(n)
  n++                 // ¡si no cambias n, bucle infinito!
}

do {
  console.log("al menos una vez")
} while (false)       // mira la condición DESPUÉS
  • while: si la condición es falsa desde el principio, no entra nunca.
  • do-while: entra siempre al menos una vez y luego comprueba.

Diagrama: cómo da vueltas un for

Antes de cada vuelta pregunta. Si la respuesta es sí, ejecuta lo de dentro, suma 1 a i y vuelve a preguntar. Cuando la respuesta es no, sale y sigue con lo que hay debajo del bucle.

for…of: recorrer una lista elemento a elemento

const frutas = ['Pera', 'Manzana', 'Platano']
for (let fruta of frutas) {
  console.log(fruta)   // Pera, luego Manzana, luego Platano
}

En cada vuelta, fruta vale el siguiente elemento. No necesitas i ni .length. Es la forma más cómoda de recorrer arrays (ver Arrays).

Funciones

Una función es un trozo de código con nombre que puedes usar todas las veces que quieras. Escribes la lógica una vez y la reutilizas (DRY: Don't Repeat Yourself, no te repitas).

Lo esencial

  • Una función es una receta: se declara una vez y no hace nada hasta que la llamas.
  • Los parámetros son los ingredientes: function sumar(a, b) → sumar(2, 3).
  • return devuelve el resultado para usarlo fuera; console.log solo lo enseña.
  • Cuando llega a un return, la función se acaba. En los bucles, el return va después del for.
  • Lo creado dentro de una función solo existe dentro (ámbito).

Las dos partes: declarar y llamar

// 1. DECLARACIÓN: las reglas del juego (aún no se ejecuta)
function sumar() {
  let suma = 12 + 4
  console.log(suma)
}

// 2. LLAMADA: aquí sí se ejecuta
sumar()   // 16
sumar()   // 16 otra vez

Sin los paréntesis () no se ejecuta. Escribir sumar solo nombra la función.

Diagrama: qué pasa al llamar a una función

1. La llamada manda los valores (2 y 3) a los parámetros (a y b). 2. La función hace su trabajo y con return devuelve el resultado al sitio desde donde la llamaste, que se guarda en r.

console.log dentro de la función solo enseña el valor; no lo devuelve. Para usar el resultado fuera, hace falta return.

Parámetros y return

function sumar(numero1, numero2) {  // parámetros: los "huecos"
  return numero1 + numero2          // devuelve el resultado
}

let resultado = sumar(2, 3)        // argumentos: lo que metes en los huecos
console.log(resultado)             // 5
  • Parámetros: datos que la función necesita para trabajar.
  • return: devuelve un valor para guardarlo en una variable. Después del return la función termina.
  • console.log solo enseña el valor por pantalla; return te lo da para seguir usándolo.

Parámetros por defecto (opcionales)

function nombreCompleto(name, surname = "Lopez") {
  console.log(`${name} ${surname}`)
}
nombreCompleto('Juan')           // Juan Lopez
nombreCompleto('Juan', 'Perez')  // Juan Perez

Si no le pasas ese dato, usa el valor por defecto.

Orden obligatorio: primero los parámetros obligatorios y al final los opcionales.

Funciones que usan otras funciones

function sumar(a, b, c, d) { return a + b + c + d }
function dividir(a, b) { return a / b }

function media(n1, n2, n3, n4) {
  let suma = sumar(n1, n2, n3, n4)
  return dividir(suma, 4)
}
console.log(media(4, 5, 8, 3))   // 5

Descomposición en acción: cada función hace una sola cosa y luego las combinas.

Ámbito (scope): dónde existe una variable

let global = "me ven en todo el archivo"

function restar(n1, n2) {
  let resultado = n1 - n2   // local: solo existe aquí dentro
  return resultado
}
console.log(resultado)      // ✘ Error: resultado no existe fuera
  • Global: declarada fuera de todo. Se usa desde cualquier sitio.
  • Local / de bloque: declarada dentro de una función o de unas llaves { } con let/const. Solo existe ahí y desaparece al terminar.
  • Por eso varias funciones pueden tener su propia variable resultado sin chocar.

Los 3 tipos de funciones

// 1. Declarativa
function multiplicar(a, b) {
  return a * b
}

// 2. Expresiva o anónima (sin nombre, guardada en una const)
const multiplicar2 = function (a, b) {
  return a * b
}

// 3. Flecha (arrow function)
const multiplicar3 = (a, b) => a * b
  • Declarativa: tiene hoisting, puedes llamarla incluso en una línea anterior a donde la escribiste.
  • Expresiva y flecha: sin hoisting, hay que declararlas antes de usarlas.
  • Las tres se llaman igual: multiplicar(2, 4) → 8.

Receta: convertir a función flecha

  1. Quita la palabra function y pon => después de los paréntesis.
  2. Si tiene un solo parámetro (ni 0 ni 2), puedes quitar los paréntesis.
  3. Si dentro de las llaves hay una sola línea, puedes quitar las llaves. Si esa línea tiene return, tienes que quitarlo (se devuelve solo).
// antes
const doble = function (n) { return n * 2 }
// paso 1
const doble = (n) => { return n * 2 }
// paso 2 y 3
const doble = n => n * 2

// con ternario, del profe:
const restar = (a, b) => (a >= b) ? a - b : b - a

Parámetros indefinidos (rest ...)

function sumar(...numeros) {   // numeros es un array

Arrays (listas)

Un array es una lista ordenada de valores guardada en una sola variable.

Lo esencial

  • Las posiciones empiezan en 0. length cuenta desde 1: la última está en length - 1.
  • Una posición que no existe da undefined.
  • lista.push(x) añade al final (funciona aunque sea const).
  • Los [ ] solo en arrays: precios[2]. Una variable normal va sin ellos.
  • Con [ ] a un texto sacas una letra: "Marta"[0] → "M".

Crear y leer

  • El último está en length - 1.
  • Se declaran con const: la variable siempre será ese array, pero puedes cambiar lo que hay dentro.
  • Un texto funciona parecido: 'Marta'[0] → 'M'.

Clase 9 (26/10, sesión 5 especial). El puente entre SQL y JavaScript: lo que en la base de datos es una fila, en JS es un objeto; y la tabla entera, un array de objetos.

Lo esencial

1 · Qué es una base de datos

¿Para qué sirve una base de datos?

  • Persistencia: los datos sobreviven a recargas, apagones y reinicios.
  • Integridad: reglas que impiden datos sin sentido (edades negativas, pedidos sin cliente).
  • Seguridad: usuarios y permisos; cada uno ve y toca solo lo suyo.
  • Concurrencia: miles de usuarios leyendo y escribiendo a la vez sin pisarse.
  • Consultas rápidas: encontrar un registro entre millones en milisegundos.
  • Copias y recuperación: backups y transacciones: o se guarda todo, o no se guarda nada.

Los arrays paralelos (alumnos, notas, faltas) son justo lo que en una base de datos sería una tabla con tres columnas.

Arquitectura en 3 capas

Frontend⇄Backend⇄Base de datos
  1. Frontend (cliente): HTML, CSS y JavaScript. Lo que ve el usuario.
  2. Backend (servidor): la lógica, por ejemplo con Node.js. Recibe las peticiones.
  3. Base de datos: donde se guarda todo (MySQL, MongoDB).

Regla de oro: el frontend nunca habla directamente con la base de datos. Todo pasa por el backend.

Como un restaurante: el comedor es el frontend, el camarero el backend y la despensa la base de datos. El cliente nunca entra en la despensa: se lo pide al camarero.

Tablas, filas, columnas y claves

  • Tabla: la información de una cosa (pokémon, alumnos…). Como un array de objetos.
  • Fila (registro): un elemento concreto.
  • Columna (atributo): un dato que tienen todos (nombre, edad…).
  • Clave primaria (PK): identificador único de cada fila. No se repite nunca (normalmente id).
  • Clave foránea (FK): columna que apunta a la PK de otra tabla para enlazarlas.

  • Nunca se guardan archivos (fotos, vídeos, PDF) dentro de la base de datos: la llenan, las consultas van lentas y las copias de seguridad pesan muchísimo.

SELECT: pedir datos

  • Las sentencias acaban en ;. Con una sola consulta algunas herramientas no lo exigen, pero en cuanto hay varias seguidas es obligatorio: mejor ponerlo siempre.
  • Las palabras de SQL se escriben en MAYÚSCULAS por costumbre, para distinguirlas de los nombres de tablas y columnas.

AND, OR, NOT, IN, BETWEEN

Son los mismos que en JS: AND = &&, OR = ||, NOT = !.

-- Paréntesis para mezclar AND y OR
WHERE (tipo = 'Fuego' OR tipo = 'Agua') AND ataque > 80

Ojo con mezclar: AND va antes que OR (como multiplicar antes que sumar). Sin paréntesis, lo de arriba significaría "los de Fuego (con cualquier ataque) o los de Agua con ataque > 80". Si mezclas, pon paréntesis siempre.

WHERE pais IS NULL          -- la casilla está vacía
WHERE pais IS NOT NULL      -- la casilla tiene algo

Ojo: para preguntar si algo está vacío se usa siempre IS NULL, nunca = NULL (con = no te sale nada).

LIKE: buscar por partes del texto

  • % = cualquier cantidad de letras (incluso ninguna).
  • _ = exactamente una letra.
WHERE nombre LIKE 'Char%'    -- empieza por "Char"
WHERE nombre LIKE '%chu%'    -- contiene "chu"
WHERE nombre LIKE '%ite'     -- termina en "ite"
WHERE nombre LIKE '_e%'      -- la 2ª letra es "e"

Es como el ejercicio de buscar nombres por letra de clase, pero sin bucle: lo hace la base de datos.

ORDER BY, LIMIT y DISTINCT

SELECT * FROM pokemon ORDER BY ataque DESC;   -- de mayor a menor
SELECT * FROM pokemon ORDER BY nombre;        -- ASC (de menor a mayor) por defecto
SELECT * FROM pokemon ORDER BY tipo, ataque DESC;  -- por tipo y, dentro de cada tipo, por ataque
SELECT * FROM pokemon LIMIT 5;                -- solo las 5 primeras filas
SELECT DISTINCT tipo FROM pokemon;            -- cada tipo una sola vez

Top 3: ORDER BY ataque DESC LIMIT 3 = los 3 con más ataque.

GROUP BY y HAVING

SELECT generacion, COUNT(*) AS total
FROM pokemon
GROUP BY generacion
HAVING total > 5;
  • GROUP BY junta las filas que tienen el mismo valor (por ejemplo, misma generación) y aplica la función a cada grupo.
  • WHERE filtra filas, antes de agrupar.
  • HAVING filtra grupos, después de agrupar.
  • La columna del GROUP BY va también en el SELECT, si no, no sabes de qué grupo es cada número.
  • Constrúyelo por pasos: primero el COUNT(*) solo, luego añades el GROUP BY, luego el HAVING y al final el ORDER BY. Si falla, sabes qué paso lo ha roto.

Matiz: usar el alias en HAVING total > 5 funciona en MySQL. En otras bases de datos hay que repetir la función: HAVING COUNT(*) > 5.

Orden de las partes de una consulta

Se escriben siempre en este orden (las que no uses, te las saltas):

SELECT→FROM→JOIN→WHERE→GROUP BY→HAVING→ORDER BY→LIMIT
SELECT tipo, AVG(ataque) AS media
FROM pokemon
WHERE generacion = 1
GROUP BY tipo
HAVING media > 70
ORDER BY media DESC
LIMIT 3;

En castellano: de los pokémon de la 1ª generación, agrúpalos por tipo, quédate con los tipos cuya media de ataque pase de 70 y enséñame los 3 mejores.

Para acordarte: Si Fulano Juega Wii, Gana Hasta Ocho Ligas (SELECT, FROM, JOIN, WHERE, GROUP BY, HAVING, ORDER BY, LIMIT).

Diagrama: en qué orden lo procesa la base de datos

Se escribe empezando por SELECT, pero la base de datos lo ejecuta en este otro orden: primero coge la tabla, filtra, agrupa… y elige las columnas casi al final.

Por eso WHERE no puede usar COUNT(*): cuando se ejecuta WHERE, los grupos todavía no existen. Para filtrar por un recuento se usa HAVING.

3 · Varias tablas y subconsultas

JOIN: juntar varias tablas

Se une por la columna que conecta las tablas: la FK de una con la PK de la otra. En la base de series:

series.plataforma_id → plataformas.idvaloraciones.usuario_id → usuarios.idvaloraciones.serie_id → series.id
-- Dos tablas: título + nombre de la plataforma
SELECT s.titulo, p.nombre
FROM series s
JOIN plataformas p ON s.plataforma_id = p.id;

-- Tres tablas: lo que ha valorado Lucía (valoraciones hace de puente)
SELECT s.titulo, v.puntuacion
FROM valoraciones v
JOIN usuarios u ON v.usuario_id = u.id
JOIN series   s ON v.serie_id   = s.id
WHERE u.nombre = 'Lucía';

-- «Lo que no tiene pareja»: plataformas sin series
SELECT p.nombre
FROM plataformas p
LEFT JOIN series s ON s.plataforma_id = p.id
WHERE s.id IS NULL;
  • s, p, u, v son apodos de las tablas, para no escribir el nombre entero. s.titulo = la columna titulo de la tabla series.
  • El ON dice por dónde se cosen las dos tablas: casi siempre FK = PK.
TipoQué devuelveEjemplo: Netflix y HBO tienen series, Filmin no
JOINSolo las filas que tienen pareja en las dos tablasSalen Netflix y HBO. Filmin desaparece.

4 · Crear y modificar

Subconsultas, NOT IN y COUNT(DISTINCT)

Una subconsulta es un SELECT dentro de otro, entre paréntesis. Se ejecuta primero y su resultado lo usa la consulta de fuera.

-- Devuelve UN valor: pokémon con más ataque que la media
SELECT nombre, ataque
FROM pokemon
WHERE ataque > (SELECT AVG(ataque) FROM pokemon);

-- Devuelve UNA LISTA: plataformas que no tienen ninguna serie
SELECT nombre
FROM plataformas
WHERE id NOT IN (SELECT plataforma_id FROM series);

-- Contar sin repetir: cuántos usuarios distintos han valorado
SELECT COUNT(DISTINCT usuario_id) AS usuarios
FROM valoraciones;
  • Así la media la calcula la consulta: si cambian los datos, se recalcula sola. No escribas el número a mano.
  • NOT IN = "que no esté en esta lista". Lo mismo se hace con LEFT JOIN … WHERE … IS NULL.
  • COUNT(DISTINCT col) cuenta valores distintos. Tras un JOIN, COUNT(*) cuenta filas, y un mismo pedido o usuario puede salir varias veces.

Ojo con NOT IN: si la subconsulta devuelve algún NULL, no sale nada. Con LEFT JOIN … IS NULL no pasa.

Subconsulta correlacionada y fechas

-- Pokémon con más ataque que la media DE SU generación
SELECT p.nombre, p.ataque, p.generacion
FROM pokemon p
WHERE p.ataque > (SELECT AVG(p2.ataque)
                  FROM pokemon p2
                  WHERE p2.generacion = p.generacion);

-- Agrupar por mes: DATE_FORMAT convierte la fecha en '2026-01'
SELECT DATE_FORMAT(fecha, '%Y-%m') AS mes, COUNT(*) AS total
FROM pedidos
GROUP BY mes
ORDER BY mes;
  • Correlacionada: la subconsulta usa una columna de la de fuera (p.generacion), así que se calcula otra vez para cada fila. Hacen falta dos alias de la misma tabla (p y p2).
  • DATE_FORMAT(fecha, formato): %Y año, %m mes, %d día.

Crear la base de datos y las tablas

Crear y cambiar la estructura se llama DDL (CREATE, ALTER, DROP). Meter y cambiar datos es DML (INSERT, UPDATE, DELETE) y consultar es DQL (SELECT).

CREATE DATABASE seriesdb;   -- crea la base de datos
USE seriesdb;               -- trabaja dentro de ella

CREATE TABLE plataformas (
  id             INT AUTO_INCREMENT PRIMARY KEY,
  nombre         VARCHAR(50) NOT NULL UNIQUE,
  precio_mensual DECIMAL(5,2)
);

CREATE TABLE series (
  id            INT AUTO_INCREMENT PRIMARY KEY,
  titulo        VARCHAR(100) NOT NULL,
  plataforma_id INT NOT NULL,
  nota          DECIMAL(3,1),
  finalizada    BOOLEAN DEFAULT FALSE,
  FOREIGN KEY (plataforma_id) REFERENCES plataformas(id)
);

Primero se crea la tabla a la que se apunta (plataformas) y luego la que tiene la FK (series). Al revés da error porque la FK apuntaría a algo que no existe.

Node.js y API REST

Clases 10 a 12 con Juan. Node es el backend que une lo de SQL con lo de JavaScript: recibe una petición, busca los datos y los devuelve en JSON. Ordenado por temas, de lo más general a lo más práctico.

Lo esencial

  • Node = JavaScript fuera del navegador. Una API REST devuelve datos en JSON, no páginas.
  • CRUD: GET leer · POST crear · PUT actualizar · DELETE borrar. Siempre se responde algo.
  • Pedir datos tarda: es asíncrono. Una promesa acaba en resolve o reject; se usa con await dentro de async y try / catch.
  • Proyecto: npm init con "type": "module", librerías con npm install, archivos conectados con export / import (con .js).
  • Express: app.verbo('/ruta', (req, res) => { … }) + app.listen(3000). Se arranca con npm run dev y se para con Ctrl + C.
  • Datos por la URL → req.params (siempre texto). Datos por el cuerpo → req.body (necesita app.use(express.json())).
  • Buscar uno → find (o undefined). Buscar varios → filter (o []).

1 · Qué es una API REST

Por qué existe una API REST

  • Antes: el backend (PHP, Java…) pedía los datos y él mismo montaba el HTML de la página.
  • Con los móviles, la misma tienda necesitaba web y apps (iOS, Android) con la misma base de datos. Un equipo para cada cosa: carísimo.
  • 2010, Node.js: JavaScript sale del navegador y puede funcionar en un servidor.
  • La solución: un "traductor" en medio. El backend ya no devuelve HTML, devuelve datos en JSON, y los entiende cualquiera: la web en React, la app, una Smart TV…

Ejemplo: la web de la Dragon Ball API enseña a Goku con su foto. En su dirección /api/characters ves los mismos datos en crudo, en JSON. Eso es lo que hace Node: los datos, sin dibujo.

2 · Asincronía y promesas

Síncrono y asíncrono

  • Síncrono: JS va línea a línea; hasta que no acaba una, no empieza la siguiente.
  • El problema: pedir algo a una base de datos o a internet tarda. Si todo esperase en fila, la web se congelaría.
  • Asíncrono: JS encarga la tarea lenta, sigue con lo demás y la recoge cuando llega.
setTimeout(() => {
    console.log('Hola')
}, 3000)              // espera 3 segundos

console.log('Adiós')

// Sale primero "Adiós" y a los 3 segundos "Hola"

A veces sí hay que esperar: si la línea siguiente usa los datos que pediste, necesitas que lleguen antes. Para eso están las promesas.

Promesas: resolve, reject, await y try/catch

Una promesa es una tarea que acabará más tarde, bien o mal.

function pedirNota(nota) {
    return new Promise((resolve, reject) => {
        if (nota >= 0 && nota < 5) {
            resolve('Suspenso')          // resultado esperado
        } else if (nota >= 5 && nota <= 10) {
            resolve('Aprobado')          // resultado esperado
        } else {
            reject('Nota no válida')     // algo inesperado: 'Pepe', 100…
        }
    })
}

async function mostrar() {
    try {
        const resultado = await pedirNota(7)   // espera a que acabe
        console.log(resultado)                 // Aprobado
    } catch (error) {
        console.log(error)                     // Nota no válida
    }
}
mostrar()
PiezaQué es
new Promise((resolve, reject) => { … })crea la promesa; la estructura es siempre esta
resolve(valor)acaba bien: resultado esperado
reject(error)acaba mal: algo inesperado
await"espera a que acabe" antes de seguir; solo dentro de async
try { } catch { }lo del resolve sigue en el try; lo del reject salta al catch
.then(…).catch(…)la otra forma de usarlas: .then recibe el resolve y .catch el reject

¿Resolve o reject? Un suspenso o un array vacío no son errores: son resultados esperados (resolve). Es reject cuando algo falla de verdad: un error de SQL o un dato sin sentido. Lo importante ahora es saber usarlas con await, porque las consultas a la base de datos devuelven promesas.

Rutas estáticas y dinámicas

// Estática: siempre la misma URL
app.get('/nombre', (req, res) => res.send('Juan Antonio'))

// Dinámica: con dos puntos, esa parte cambia
app.get('/producto/:nombre/:precio', (req, res) => {
    console.log(req.params)   // { nombre: 'carne', precio: '100' }
    res.send(`Mis parámetros son ${req.params.nombre} y ${req.params.precio}`)
})
  • /producto/carne/100 → carne y 100. req.params es un objeto con las partes dinámicas.
  • Lo que llega por req.params es siempre texto ('100'). Para números: Number(req.params.id). Compruébalo con typeof.

Cuándo dos rutas son la misma

  • Un parámetro con : es una cajita que admite cualquier cosa. /pais/:nombre y /pais/:id son la misma ruta.
  • Con el mismo verbo, Express usa la primera que esté escrita; la otra nunca se ejecuta.
  • Ruta = verbo + dirección. GET /pais/:pais y DELETE /pais/:id conviven sin problema.
  • Por eso se pone una parte fija delante: /pais/id/:id ya no choca con /pais/:nombre.

6 · CRUD con un array de países

Chuleta: las cuatro rutas del CRUD

// data.js
export const arrayPaises = [
    { id: 1, pais: 'España',   capital: 'Madrid' },
    { id: 2, pais: 'Francia',  capital: 'Paris' },
    { id: 3, pais: 'Alemania', capital: 'Berlin' },
    { id: 4, pais: 'Rusia',    capital: 'Moscú' }
]

// index.js
import { arrayPaises, sanitize } from './data.js'

// GET: buscar un país por nombre (URL)
app.get('/pais/:pais', (req, res) => {
    const country = sanitize(req.params.pais)
    const data = arrayPaises.find(item => sanitize(item.pais) === country)
    if (data !== undefined) {
        res.json(data)
    } else {
        res.send('este pais no esta en mi BBDD')
    }
})

// POST: crear un país (body)
app.post('/new/pais', (req, res) => {
    const nuevoPais = req.body
    arrayPaises.push(nuevoPais)
    res.json(arrayPaises)
})

// PUT: actualizar un país (id por URL + datos por body)
app.put('/update/pais/:id', (req, res) => {
    const data = req.body
    const id = Number(req.params.id)
    const dataPais = arrayPaises.find(pais => pais.id === id)
    dataPais.capital = data.capital
    res.json(dataPais)
})

// DELETE: borrar un país (id por URL)
app.delete('/pais/:id', (req, res) => {
    const id = Number(req.params.id)
    const resultado = arrayPaises.filter(pais => pais.id !== id)
    res.json(resultado)
})

No hay persistencia: lo que crees o cambies vive en memoria; al reiniciar el servidor, el array vuelve a ser el de data.js. Guardar de verdad es cosa de la base de datos.

GET: buscar y responder siempre

  • Si find no encuentra nada devuelve undefined, y undefined.capital rompe el servidor. Por eso el if: es el "no hay resultados" de cualquier buscador.
  • if (data !== undefined) y if (data) hacen lo mismo: undefined cuenta como falso.
  • Compara país con país (item.pais), no con la capital.
  • En MySQL no hace falta toLowerCase: por defecto no distingue mayúsculas.

Tildes y ñ: la función sanitize

export function sanitize(palabra) {
    let resultado = palabra.toLowerCase()       // 'Irán' → 'irán'
    resultado = resultado.replaceAll('á', 'a')  // 'irán' → 'iran'
    resultado = resultado.replaceAll('é', 'e')
    resultado = resultado.replaceAll('í', 'i')
    resultado = resultado.replaceAll('ó', 'o')
    resultado = resultado.replaceAll('ú', 'u')
    resultado = resultado.replaceAll('ñ', 'n')
    return resultado
}
  • Se limpian los dos lados antes de comparar: lo que llega y lo del array. El array no cambia: solo se compara una copia limpia.
  • En nombres de archivos, carpetas y rutas, mejor sin espacios, tildes ni ñ: en una URL se codifican (un espacio es %20). Usa _ o -.

POST: crear con el body

  • Para mandar un objeto entero se usa el cuerpo de la petición: req.body. Necesita app.use(express.json()) justo después de const app = express(); sin eso, req.body es undefined.
  • En el cliente: verbo POST y pestaña Body → JSON.
  • Así conectan front y back: en React capturarás un formulario, montarás este objeto y lo mandarás por POST.
{ "id": 5, "pais": "Finlandia", "capital": "Helsinki" }

JSON estricto (el del body): claves y textos con comillas dobles, y sin coma después del último dato. El id va a mano; en MySQL se pone solo (autoincremental).

PUT: actualizar (params + body)

  1. Buscar el país por id con find (el id pasado a número).
  2. Cambiar la propiedad: dataPais.capital = data.capital.
  3. Responder con el país actualizado: res.json(dataPais).

Ojo: si el id no existe, dataPais es undefined y el servidor da error 500. Habría que comprobar if (dataPais) antes de cambiarlo.

DELETE: borrar por id

  • Truco típico: borrar = quedarte con todos menos ese, con filter(pais => pais.id !== id).
  • Otros métodos: pop() borra el último, shift() el primero y splice(posición, 1) uno en una posición (pero necesitas la posición, no el id).

Ojo: filter crea un array nuevo: arrayPaises sigue igual y un GET posterior todavía encuentra el país. Con base de datos se hará un DELETE y luego un SELECT.

Borrado físico y lógico: el físico es el DELETE. El lógico es un campo tipo activo a 0 o 1: el usuario desaparece, pero los datos se quedan (las tiendas, por ley, guardan las compras unos años).
